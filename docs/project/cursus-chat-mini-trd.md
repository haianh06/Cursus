# Cursus Chat — Mini TRD

## Boundaries

- `backend/` owns FastAPI, database migrations, authentication, Student APIs,
  persistence, and orchestration boundaries.
- `ai-service/` owns model clients, routing, prompts, guardrails, RAG
  composition, and streaming generation. It never accepts a browser request or
  database credential directly.
- `frontend/` owns the React panel, briefing, source rendering, and explicit
  action confirmations.

## Model routing

The AI service classifies a request with deterministic signals (intent,
retrieval breadth, requested operation, and message complexity). Simple
grounded facts and product help use `OPENAI_LIGHT_MODEL`; multi-source
explanations, plan proposals, reflection summaries, and ambiguous complex
questions use `OPENAI_STRONG_MODEL`. Model names stay environment-configurable.

## Core contracts

The Student chat stream emits SSE events: `meta`, `delta`, `citation`,
`action_preview`, `done`, and `error`. Citations are generated by server-side
retrieval and never trusted from model text. Action proposals are typed,
owner-scoped, short-lived, and require a separate confirm endpoint.

## Data lifecycle

Conversation, message, summary, action proposal, and briefing-impression rows
carry an expiry timestamp. A cleanup command hard-deletes expired records;
owner export and deletion endpoints use the same ownership policy.

## Safety

Input guardrails run before model routing. Academic-integrity blocks return a
Socratic alternative; safety signals return a fixed crisis-safe response;
tool calls are allowlisted and authorization is rechecked at execution time.
